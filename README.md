# Isaac Lab Training Workbench

独立运行的 Isaac Lab 实验工作台。石墨薄荷绿 / 冰川白蓝双主题；通过现有训练入口和 Hydra 覆盖启动任务，参数不写回训练源码。

本机入口：**http://127.0.0.1:8765**。默认项目是同级 `AME_Locomotion`，训练 Python 为 `env_ame`，独立安装的 Isaac Sim 为 `C:/isaacsim`。连接信息可以在“本机设置”修改或添加。

移除项目：顶部选择项目 → 本机设置 → 删除项目连接 → 确认移除连接。项目及其工作流、实验记录将从工作台中移除，本地代码、模型和日志文件保留。运行中的项目需要先停止训练；移除最后一个项目后可重新添加连接。

## 启动

本机依赖已经安装，双击 `start.cmd` 即可打开工作台。`status.cmd` 查看状态，`stop.cmd` 暂停队列并停止服务。关闭浏览器不影响训练；停止工作台服务也会保留已启动的独立监督训练，重新启动后继续观察。

首次在其他机器安装，需要 Python 3.11+、Node.js 22.12+ 或 24，以及已经可以运行训练的 Isaac Lab 环境。

```powershell
# Windows：在工作台目录中执行
.\setup.cmd
.\start.cmd
```

```bash
# Linux：在工作台目录中执行
bash setup.sh
bash start.sh
.venv/bin/python -m workbench.cli status
.venv/bin/python -m workbench.cli stop
```

服务使用工作台自己的 `.venv`。训练和配置读取使用项目档案中指定的训练 Python，两者独立。修改前端源码后在 `frontend` 执行 `npm.cmd run build`（Linux 使用 `npm run build`）；服务直接提供构建后的页面。

## 安排实验

1. 在“本机设置”确认项目路径、Python、任务 ID、任务注册模块。独立安装 Isaac Sim 时填写其根目录；pip 安装时留空。额外环境变量可填写 JSON 对象。
2. 点击“刷新配置”。工作台用训练 Python 初始化 Isaac Lab、导出真实默认配置后退出，不创建训练环境。已有训练期间不能刷新。
3. 新建工作流，添加实验。可编辑名称、本次新增迭代数、环境数、seed、设备、保存间隔、视频选项、奖励权重和已导出的门控标量。“无限制”会发送 `null`，映射 Python 的 `None`。
4. 选择训练方式和 checkpoint 来源。参数网格会展开笛卡尔积，先预览，再批量加入队列。单次最多 1000 项。
5. 点击“启动工作流”。前项成功退出且最终 checkpoint 通过检查后自动启动后项。可以在实时日志、运行详情和训练产物中检查结果。

| 方式 | 行为 |
|---|---|
| 从头训练 | 从项目默认初始化开始 |
| 接续训练 / resume | 恢复模型、优化器、迭代计数 |
| 仅加载权重 / warm start | 使用项目的 `--finetune_from`，重置优化器与迭代计数 |

`max_iterations` 是**本次新增更新数量**。当前 RSL-RL 加载编号 K 后，从编号 K 开始继续记录：例如 checkpoint 编号 1 再训练 2 次，最终编号为 2。这是训练 runner 的原生编号方式，不表示只训练了一次。

checkpoint 可以选本机文件，也可以选本工作流中排在前面的实验。后者使用该次成功运行真正生成的最终文件，适合串联实验。每次运行保存独立命令、配置和源码指纹；已执行实验的配置不可改写，调整参数请“复制实验”。重试创建新的运行尝试。

## 暂停、失败与恢复

“实验记录”列表和运行详情提供“删除记录”；队列右键菜单提供“删除实验”。删除前会确认范围。默认只删除列表记录并保留模型和日志；需要释放空间时，可勾选“同时删除本次训练文件”，删除本次时间戳目录内的模型、TensorBoard 和视频等文件，并清空文字日志。此操作不可撤销；被其他实验引用的 checkpoint、运行中的任务和不属于本次运行的目录受到保护。工作台内部保留少量执行证据以维持尝试编号。

添加/编辑实验和运行详情均提供“笔记”页签，同一实验共享一条笔记（包括重新尝试的运行）。编辑配置时点击“保存实验”一并保存配置和笔记，运行详情中点击“保存笔记”。支持中文与多行文字，最多 20,000 字；切换页签保留草稿，关闭弹窗或刷新页面时提醒未保存的笔记。旧版运行笔记会兼容读取；同一实验如有多次运行笔记，采用最近编辑的一条，原数据仍保留。工作流导入/导出包含笔记。笔记不修改训练配置快照或训练文件。

底部“清空文字日志”会真正截断磁盘上的 console.log，刷新页面后不会恢复旧文字；当前训练继续，新输出仍会追加。新启动任务的单份文字日志最多保留最近 10 MB，超过后滚动保留较新内容。清空文字日志不删除模型或 TensorBoard 数据。

- “暂停队列”让当前训练正常完成，之后不再启动下一项。
- “停止当前训练”终止它并暂停队列，保留已经写出的 checkpoint；不能保证额外保存退出前的最后状态。
- 失败会暂停整个队列。检查日志后重试、复制修改或跳过；依赖失败项的后续任务会阻塞，必须修正 checkpoint 来源。
- 已在命令行启动的同项目训练会被自动检测。也可在设置页检查进程，选择“等待此进程”；队列等它退出，不接管它的停止与产物。
- 训练源码或项目连接变化后，队列会暂停。刷新配置、检查变化，再点“更新基线”。工作台代码与训练日志不计入训练源码指纹。
- 关闭网页、重启 API 都不停止独立训练。`stop.cmd` 会暂停后续任务，重新 `start.cmd` 后确认并继续队列。电脑重启或监督进程意外消失时，任务标为中断，不自动重复启动。

阶段来自项目源码中的 `FINETUNE` 配置，只读展示。在项目中修改阶段后重新刷新配置；阶段二必须指定 resume 或仅加载权重。

## 数据与迁移

```text
frontend/              React + TypeScript 界面
backend/workbench/     FastAPI、SQLite、调度 worker、运行 supervisor
adapters/              独立的配置导出与 checkpoint 检查工具
data/                  数据库、配置缓存、服务日志、进程身份
outputs/attempts/<id>/ 配置快照、有容量上限的 console.log、进度和退出记录
design/                已确认的主题规范、深浅预览和原始图标参考
```

新启动或重试实验的训练产物保存到所连接训练项目的 `logs/rsl_rl/<任务目录>/<时间戳>_<实验名>/`，包含原生 params、模型、视频和 TensorBoard 事件文件。任务目录读取原训练配置的 `experiment_name`，例如 `go2_ame`；刷新配置后会同步读取。不再使用运行 ID 作为训练目录。工作台仅从本次时间戳目录读取结果，避免选到同任务下其他实验的模型。已有结果保留原路径，checkpoint 接续和产物查询继续按运行记录中的绝对路径访问。

`WORKBENCH_DATA_DIR`、`WORKBENCH_OUTPUT_DIR` 仅调整工作台数据库、控制日志、进度快照等存储位置；修改前先停工作台服务并确认没有训练在运行。

“导出项目档案”和工作流“导出 / 导入”用于迁移实验计划，工作流依赖会重新映射为新机器的实验 ID。详细说明见 [迁移与适配](docs/PORTABILITY.md)。初次迁移建议使用档案和工作流导入，重新建立运行历史。
